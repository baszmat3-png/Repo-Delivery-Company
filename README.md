# ريوو للتوصيل اسرع

منصة توصيل بثلاث واجهات في تطبيق واحد: **تاجر** و**سائق** و**مدير (لوحة التحكم)**.
موقع (PWA) + خادم Node.js + قاعدة PostgreSQL + تطبيق أندرويد لمتجر Play.

```
web/      الواجهة (HTML/CSS/JS بدون بناء) + صفحة الخصوصية + صفحة حذف الحساب
server/   الخادم (API) ويقدّم الموقع أيضاً. يعمل على PostgreSQL (Render) أو SQLite محلياً
android/  يُولَّد تلقائياً بواسطة Capacitor أثناء البناء (لا يُرفع للمستودع)
```

## ما الذي يفعله كل حساب

| الحساب | الصلاحيات |
|---|---|
| **تاجر** | إنشاء طلب (منطقة الزبون، رقمه، المنتج، العدد، دراجة/سيارة، سعر التوصيل، سعر المنتج، ملاحظة)، إحصائيات الطلبات، إلغاء الطلب قبل قبوله، محادثة مع السائق |
| **سائق** | رؤية الطلبات المتاحة وقبولها (يُخصم رسم التطبيق 500 أو 1000 د.ع)، تغيير حالة الطلب (في الطريق، تم التسليم، لا يرد، مشكلة، راجع، راجع جزئي…)، محفظة وشحن ببطاقة، تقارير الأرباح، تفعيل/إيقاف استقبال الطلبات |
| **مدير** | نظرة عامة، كل الطلبات وتغيير حالتها أو إعادتها للسائقين (مع إرجاع الرسوم)، إضافة/تعديل/إيقاف التجار والسائقين، شحن أو خصم رصيد يدوي، توليد كروت الشحن، تعديل الأسعار والرسوم ورقم الدعم |

الحسابات يُنشئها المدير فقط (لا يوجد تسجيل عام).

## التشغيل محلياً

يتطلب Node 22.13 أو أحدث. لا حاجة لتثبيت أي حزمة محلياً (SQLite مدمج في Node).

```bash
cd server
node index.js          # http://localhost:3000
```

عند التشغيل بدون `DATABASE_URL` تُحمَّل بيانات تجريبية (كلمة مرور الجميع `123456`):

| الدور | الهاتف |
|---|---|
| مدير | `07700000000` / كلمة المرور `admin1234` |
| تاجر | `07700000201` (الرافدين) · `07700000202` · `07700000203` |
| سائق | `07700000301` (علي كريم) · `07700000302` |

اختبار API كامل (46 فحصاً): شغّل الخادم ثم `node smoke-test.js` داخل `server/`.

## النشر على Render (الخادم + الموقع + قاعدة البيانات)

1. ارفع المشروع إلى GitHub (الأوامر بالأسفل).
2. في Render: **New ← Blueprint** واختر المستودع. سيقرأ `render.yaml` وينشئ الخدمة وقاعدة PostgreSQL.
3. عند السؤال أدخل `ADMIN_PHONE` (مثل `07712345678`) و`ADMIN_PASSWORD` (قوية).
4. بعد النشر افتح رابط الخدمة وسجّل الدخول كمدير، ثم أضف التجار والسائقين من لوحة التحكم.

ملاحظات: الخطة المجانية تنام الخدمة بعد فترة خمول (أول طلب يتأخر نحو دقيقة)، وقاعدة PostgreSQL المجانية في Render لها مدة صلاحية محدودة، فتحقق من خطتك الحالية وانتقل لخطة مدفوعة قبل الاعتماد عليها في عمل حقيقي. لا تضبط `SEED_DEMO=1` في الإنتاج.

## النشر على GitHub

```bash
cd rio-delivery
git init && git add . && git commit -m "ريو للتوصيل"
git branch -M main
git remote add origin https://github.com/USERNAME/rio-delivery.git
git push -u origin main
```

**GitHub Pages (اختياري):** الخادم على Render يقدّم الموقع أصلاً، لكن إن أردت نسخة Pages أيضاً:
Settings ← Pages ← Source: GitHub Actions، ثم Settings ← Variables ← أضف `RIO_API_URL` = رابط Render (بدون `/` في النهاية). يعمل سير العمل تلقائياً عند أي تعديل على `web/`.

## تطبيق أندرويد (Google Play)

التطبيق يغلّف الواجهة بـ Capacitor ويتصل بخادم Render. البناء يتم على GitHub بدون تثبيت Android Studio:

1. أضف متغير المستودع `RIO_API_URL` = رابط Render.
2. **تجربة سريعة:** Actions ← «بناء تطبيق أندرويد» ← Run workflow. نزّل ملف APK من Artifacts وثبّته على هاتفك.
3. **للنشر على Play:** أنشئ مفتاح توقيع مرة واحدة واحفظه في مكان آمن (إن ضاع لا تستطيع تحديث التطبيق):
   ```bash
   keytool -genkey -v -keystore rio.keystore -alias rio -keyalg RSA -keysize 2048 -validity 10000
   base64 -w0 rio.keystore   # انسخ الناتج
   ```
   ثم Settings ← Secrets ← أضف: `ANDROID_KEYSTORE_BASE64` و`ANDROID_KEYSTORE_PASSWORD` و`ANDROID_KEY_ALIAS` (rio) و`ANDROID_KEY_PASSWORD`.
   شغّل سير العمل مجدداً، وسيُنتج ملف `.aab` جاهزاً للرفع في Play Console.
4. رقم الإصدار (versionCode) يزيد تلقائياً مع كل تشغيل.

**متطلبات Play Console:**
- رابط سياسة الخصوصية: `https://رابط-render/privacy.html`
- رابط حذف الحساب: `https://رابط-render/delete-account.html`
- معرّف التطبيق: `com.rioiraq.delivery` (غيّره في `capacitor.config.json` قبل أول رفع إن أردت اسماً آخر، فلا يمكن تغييره بعد النشر).
- بيانات سلامة البيانات: الاسم، رقم الهاتف، كلمة المرور، سجل الطلبات والمعاملات. لا موقع ولا إعلانات.
- الحسابات الجديدة لا تُنشأ داخل التطبيق، فجهّز حساب تاجر وحساب سائق تجريبيين وضعهما في «تعليمات الوصول للتطبيق» لفريق المراجعة.

## المظهر (الثيمات)

خمسة ثيمات: أبيض، أسود، وثلاثة بتدرجات (أزرق، غروب، أخضر). تُختار من «الملف الشخصي/حسابي» في التطبيق ومن «الإعدادات» في لوحة التحكم، وتُحفظ على الجهاز.

## الإشعارات (تصل والتطبيق مغلق)

يُنشئ الخادم إشعاراً ويدفعه للهاتف عند: وصول طلب جديد، قبوله، تغيّر حالته (رفض/لا يرد/تأجيل/إرجاع/تسليم)، تحويله أو سحبه، وعمليات المحفظة (خصم رسوم، شحن بطاقة، شحن/سحب من الإدارة، استرجاع رسوم)، ورسائل المحادثة. الكل يظهر أيضاً في «قائمة الإشعارات» الكاملة (الجرس).

- **المتصفح / PWA:** Web Push جاهز بلا إعداد (مفاتيح VAPID تُولَّد وتُحفظ تلقائياً). يظهر طلب الإذن عند أول نقرة بعد الدخول.
- **تطبيق أندرويد:** يحتاج Firebase مرة واحدة:
  1. أنشئ مشروعاً في Firebase وأضف تطبيق أندرويد بمعرّف `com.rioiraq.delivery`، ونزّل `google-services.json`.
  2. أضفه كسرّ في GitHub باسم `GOOGLE_SERVICES_JSON_BASE64` (`base64 -w0 google-services.json`).
  3. من إعدادات المشروع ← Service accounts ← Generate new private key، والصق محتوى JSON في متغير Render باسم `FIREBASE_SERVICE_ACCOUNT`.
  4. أعد بناء التطبيق.
- الإشعار يصل فقط لمن سجّل الدخول، ويتوقف عنه عند تسجيل الخروج.

## الأمان

- كلمات المرور مشفّرة بـ scrypt، والجلسات رموز موقّعة (HMAC) لمدة 30 يوماً.
- كل نقطة API تتحقق من الدور، والتاجر والسائق لا يريان إلا طلباتهما.
- قبول الطلب وشحن الكرت عمليتان ذريتان: لا يقبل طلباً سائقان معاً، ولا يُستخدم الكرت مرتين.
- محاولات الدخول وإدخال أرقام الكروت محدودة لمنع التخمين.
- غيّر `ADMIN_PASSWORD` فوراً، وأبقِ `JWT_SECRET` سرياً.

## حدود الإصدار الحالي

- تحديث الطلبات يتم بالاستعلام الدوري كل 10 ثوانٍ، ولا توجد إشعارات دفع (Push) بعد.
- لا يوجد ربط بدفع إلكتروني: شحن المحفظة يتم ببطاقات يولّدها المدير.
- التسعير حسب المطابقة النصية بين منطقة المتجر ومنطقة الزبون (مع إمكانية التغيير يدوياً).
